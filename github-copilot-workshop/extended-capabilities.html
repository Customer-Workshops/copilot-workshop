Copilot CLI

15 minutes

GitHub Copilot CLI brings AI-powered assistance directly to your terminal, helping you craft shell commands, explain what commands do, and navigate your development environment more efficiently.

What is Copilot CLI?

Copilot CLI is a command-line extension that lets you ask Copilot questions in plain language directly from your terminal. It supports two key sub-commands:

  • gh copilot suggest — Suggest a shell command for a given task
  • gh copilot explain — Explain what a shell command does

Installation

Copilot CLI is available as a GitHub CLI extension. To install it:

  1. Ensure the GitHub CLI (gh) is installed and authenticated
  2. Install the extension: 
    gh extension install github/gh-copilot
  3. Verify the installation: 
    gh copilot --version

Suggesting Commands

Use gh copilot suggest to get a shell command for a plain-language description of a task:

gh copilot suggest "list all running Docker containers and their port mappings"

Copilot will suggest a command and ask whether you want to copy it to your clipboard, run it directly, or revise the request.

Explaining Commands

Use gh copilot explain to understand what an unfamiliar command does:

gh copilot explain "git rebase -i HEAD~3"

Copilot will provide a clear, plain-language explanation of the command and its flags.

Tip

You can pipe command output to Copilot explain for contextual help: cat error.log | gh copilot explain

Hands-on Exercise

  1. Ask Copilot CLI to suggest a command to find all files larger than 100 MB in your home directory
  2. Ask Copilot CLI to explain the output of ps aux | grep node
  3. Use gh copilot suggest to generate a git command that shows a compact graph of the last 10 commits across all branches

Copilot SDK

20 minutes

The GitHub Copilot SDK allows you to programmatically integrate Copilot's AI capabilities into your own applications and tools, enabling you to build custom AI-powered experiences.

What is the Copilot SDK?

The Copilot SDK (also referred to as the Copilot Extensions API) provides the building blocks to create GitHub Apps that communicate with Copilot. These extensions appear as agents within Copilot Chat and can respond to user messages with context-aware AI output.

Key Concepts

  • Copilot Extensions — GitHub Apps that integrate with Copilot Chat via a defined API contract
  • Agent endpoint — An HTTPS endpoint your app exposes that Copilot calls when a user invokes your agent
  • Server-Sent Events (SSE) — The streaming protocol used to send responses back to Copilot Chat in real time
  • Payload verification — Signature verification to ensure requests originate from GitHub

Getting Started

  1. Create a new GitHub App in your organization or personal account settings
  2. Enable Copilot under the app's permissions and set an agent URL
  3. Implement the agent endpoint in your preferred language: 
    # Example: minimal Python agent using Flask
from flask import Flask, request, Response
import json

app = Flask(__name__)

@app.route("/agent", methods=["POST"])
def agent():
    def generate():
        yield "data: " + json.dumps({
            "choices": [{
                "delta": {"content": "Hello from my custom Copilot agent!"},
                "finish_reason": None
            }]
        }) + "\n\n"
        yield "data: " + json.dumps({
            "choices": [{"delta": {}, "finish_reason": "stop"}]
        }) + "\n\n"
    return Response(generate(), mimetype="text/event-stream")

if __name__ == "__main__":
    app.run(port=3000)
  4. Install your GitHub App and invoke your agent in Copilot Chat with @your-agent-name

SDK Libraries

GitHub provides official SDK helpers to simplify agent development:

  • github-mcp-server — Reference implementation using the Model Context Protocol (GitHub repository)
  • @github/copilot-extensions — Node.js SDK for building Copilot agents
Note

Your agent endpoint must be publicly reachable over HTTPS. During development, tools like ngrok can expose a local server for testing.

Hands-on Exercise

  1. Create a minimal agent endpoint that responds with a greeting when invoked
  2. Register it as a GitHub App with Copilot permissions and test it in Copilot Chat
  3. Extend the agent to echo the user's message back with the current timestamp

Agent Skills

20 minutes

Agent Skills allow you to extend Copilot agents with callable functions — similar to tool use in modern AI models — enabling agents to take actions, retrieve data, and interact with external systems.

What are Agent Skills?

Skills (also called tools or functions) are discrete capabilities you expose to a Copilot agent. When a user asks the agent to do something, the agent can invoke a skill to fetch data or perform an action and incorporate the result into its response.

Defining a Skill

Skills are defined as JSON function schemas that describe the skill's name, description, and parameters:

{
  "type": "function",
  "function": {
    "name": "get_weather",
    "description": "Get the current weather for a given city",
    "parameters": {
      "type": "object",
      "properties": {
        "city": {
          "type": "string",
          "description": "The name of the city"
        }
      },
      "required": ["city"]
    }
  }
}

Implementing a Skill Handler

Your agent endpoint receives a function call request from Copilot and must return the result:

# Example skill handler (Python)
def handle_skill(function_name, arguments):
    if function_name == "get_weather":
        city = arguments.get("city", "Unknown")
        # Call a weather API here
        return {"temperature": "22°C", "condition": "Sunny", "city": city}
    return {"error": "Unknown skill"}

Skill Design Best Practices

  • Keep each skill focused on a single, well-defined task
  • Write clear, descriptive skill descriptions — the model uses them to decide when to call the skill
  • Return structured data (JSON) so the agent can summarize it naturally
  • Handle errors gracefully and return informative error messages
  • Validate and sanitize all inputs before using them in external calls
Tip

Skills work best when they are composable. A well-designed set of small skills can be combined by the agent to answer complex, multi-step questions.

Hands-on Exercise

  1. Define a search_docs skill that accepts a query parameter
  2. Implement a handler that searches a static list of documentation topics and returns matching results
  3. Register the skill with your agent and test it by asking your agent a question that triggers the skill

Sub-Agents

20 minutes

Sub-agents allow a primary Copilot agent to delegate tasks to specialized agents, enabling modular, multi-step workflows that combine the strengths of multiple AI agents.

What are Sub-Agents?

A sub-agent is an agent that is invoked programmatically by a parent agent rather than directly by a user. The parent agent orchestrates the workflow, deciding which sub-agent to call and how to combine results into a final response.

Architecture Overview

A typical sub-agent architecture:

  1. Orchestrator agent — Receives the user's request and decomposes it into sub-tasks
  2. Specialist sub-agents — Each handles a specific domain (e.g., code generation, data retrieval, content summarization)
  3. Aggregation — The orchestrator combines sub-agent results and returns a unified response

Implementing a Sub-Agent Workflow

# Example: orchestrator calling two sub-agents
def orchestrate(user_message):
    # Step 1: delegate research to a retrieval sub-agent
    docs = call_sub_agent("retrieval-agent", user_message)

    # Step 2: delegate code generation to a coding sub-agent
    code = call_sub_agent("coding-agent", {
        "task": user_message,
        "context": docs
    })

    return f"Here are the relevant docs:\n{docs}\n\nGenerated code:\n{code}"

def call_sub_agent(agent_name, payload):
    # Make an HTTP request to the sub-agent endpoint
    import requests
    response = requests.post(f"https://agents.example.com/{agent_name}", json=payload)
    return response.json().get("result", "")

When to Use Sub-Agents

  • When a task is too complex for a single agent to handle well
  • When different steps of a workflow require specialized knowledge or tools
  • When you want to reuse existing agents as building blocks
  • When parallel execution of independent tasks can reduce latency
Note

Keep sub-agent interfaces simple and well-documented. An orchestrator is only as reliable as its sub-agents — ensure each sub-agent returns consistent, predictable output.

Hands-on Exercise

  1. Create a summarizer sub-agent that takes a block of text and returns a bullet-point summary
  2. Create an orchestrator agent that fetches content from a URL (using a skill) and then calls the summarizer
  3. Test the workflow end-to-end by asking your orchestrator agent to summarize the GitHub Copilot documentation page

Copilot Memory

15 minutes

Copilot Memory enables agents to persist and retrieve information across conversations, allowing for more personalized, context-aware interactions over time.

What is Copilot Memory?

By default, Copilot agents are stateless — each conversation starts fresh. Memory adds a persistence layer that lets agents store facts, preferences, and context that can be recalled in future sessions.

Types of Memory

  • Short-term memory — Context maintained within a single conversation (automatically handled via the conversation window)
  • Long-term memory — Persisted facts stored in an external store (database, vector store, etc.) and retrieved on demand
  • Episodic memory — Summaries of past conversations stored and retrieved to inform future interactions

Implementing Long-term Memory

A common approach uses a vector database to store and semantically search memories:

# Example: storing and retrieving memories (Python)
from openai import OpenAI

client = OpenAI()

def store_memory(text, memory_store):
    embedding = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    ).data[0].embedding
    memory_store.append({"text": text, "embedding": embedding})

def retrieve_memory(query, memory_store, top_k=3):
    import numpy as np
    query_embedding = client.embeddings.create(
        model="text-embedding-3-small",
        input=query
    ).data[0].embedding
    scores = [
        np.dot(query_embedding, mem["embedding"])
        for mem in memory_store
    ]
    top_indices = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)[:top_k]
    return [memory_store[i]["text"] for i in top_indices]

Memory in Copilot Agents

To integrate memory into a Copilot agent:

  1. At the start of each conversation, retrieve relevant memories based on the user's message
  2. Inject the retrieved memories into the system prompt as context
  3. At the end of the conversation, extract and store key facts from the exchange
Privacy Note

Always be transparent with users about what information is being stored and provide a way for them to review or delete their stored memories.

  2. Add a remember skill that stores a key-value fact provided by the user
  3. Add a recall skill that retrieves stored facts and inject them into the agent's response
